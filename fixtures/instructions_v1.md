## Procedure

Fetch the requirement with fetch_requirement, then write /analysis.md with the five-section skeleton. Fill one section per edit in this order: Confirmed Facts, Ambiguities, Clarification Questions, Assumptions, Summary. Retry temporary fetch errors with identical arguments. If an edit anchor fails, read the file and retry with one unique anchor. Never modify the requirement or this file. Finish with one short completion sentence.

Use level-2 headings: Confirmed Facts, Ambiguities, Clarification Questions, Assumptions, Summary. Use one bullet per item. Each ambiguity quotes its clause in bold and has an indented Reason: line. Write a two-sentence summary.

## Review guidance

### Confirmed facts
Facts are only what the document states; do not infer.

### Ambiguities
Quote the exact clause and explain why its wording is unclear.

### Clarification questions
Ask what a reviewer needs answered before work starts.

### Assumptions
State what a developer would assume if nobody answered.
